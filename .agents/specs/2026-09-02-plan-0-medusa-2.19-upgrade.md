# Plan 0: Medusa 2.19 Version Bump

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump the Medusa package versions to 2.19.0 (`@medusajs/ui` to 4.2.1) and verify the plugin still builds and passes tests. Nothing else.

**Architecture:** Version fields in `package.json` only — `devDependencies` and
`peerDependencies` in lockstep. The user has already deployed this plugin on 2.19
successfully. This plan deliberately contains **no** other changes: no engines edit,
no vite bump, no README edit, no validator changes. If anything fails, the failure is
reported, not patched — remediation is a separate decision.

**Tech Stack:** Yarn 4.4.1 (`nodeLinker: node-modules`), `medusa plugin:build`, Jest 29.

## Global Constraints

- **Scope is version numbers and the lockfile. Nothing else changes in this plan.**
  Engines, vite, README, and source files are explicitly out of scope.
- All work happens on a feature branch, never `main` (see the plan index execution
  rules). Commit once, at the end, after user approval of the message.
- Code, comments, and commit messages in English (`.agents/AGENTS.md`).
- Do not add new dependencies. Do not modify generated files.

## Verified facts (npm registry, checked 2026-09-02)

- `2.19.0` is the only stable `2.19.x` release and the `latest` tag for `medusa`,
  `framework`, `admin-sdk`, `cli`, `icons`, `test-utils` (all six lockstep).
  `2.19.1-*` entries are previews/snapshots — never use them.
- `@medusajs/ui` versions independently; `latest` is `4.2.1`, and
  `@medusajs/dashboard@2.19.0` depends on exactly `4.2.1`.
- `@medusajs/ui@4.2.1` exports the complete set of 26 names this repo imports
  (verified against `dist/cjs/index.d.ts`, including the data-table re-exports).
- `@medusajs/icons@2.19.0` exports all 15 icons this repo imports.
- Known consequence (accepted, not acted on here): `zod` moves from 3.25.76 to 4.2.0
  via `@medusajs/deps`/`dashboard`/`admin-sdk`. The verification task checks
  behaviour through the existing test suites.

**Files:** none modified. This task only runs commands.

**Interfaces:**
- Consumes: Task 1's installed tree.
- Produces: pass/fail evidence. On failure: a written report, no fixes.

```bash

```

- [ ] **Step 2: Build (compiles the admin extension too)**

```bash

```


PostgreSQL with `DATABASE_URL` (see `integration-tests/medusa-config.ts`). If the
database is unavailable, report that these could not run — never report them as
passing.

`plan-offers-routes.spec.ts` asserts backend English labels (`Every month`, `10% off`)
at lines 221, 230, 306, 320. Those must still pass: label generation is untouched.
